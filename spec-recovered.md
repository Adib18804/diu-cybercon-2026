    • Full Name
    • Student ID Number
    • Department
    • University / Institution Name
    • University Email (unique)
    • Phone Number
    • T-Shirt Size (M / L / XL / XXL / XXXL)
  VERIFICATION
    • Student ID card image OR valid student proof
    • Allowed formats: JPG · JPEG · PNG · WebP
    • Max file size: admin-configurable
    • Server-side validation: extension + MIME + size + integrity
    • Stored PRIVATELY, never publicly accessible

REGISTRATION WIZARD (12-step flow, segmented)
  STEP 01  Select Event (CTF / Trace / Poster / Project / Workshop / 
           Panel)
  STEP 02  Choose Individual / Team (auto-determined by module)
  STEP 03  Participant Information (leader / self)
  STEP 04  Student Verification upload
  STEP 05  Team Information (if team event)
  STEP 06  Add Team Members (dynamic — one card per member, each with 
           full info + student ID upload)
  STEP 07  Review all information
  STEP 08  Accept rules & terms
  STEP 09  Submit registration
  STEP 10  Generate unique Registration ID (e.g. CYB26-XXXXXX)
  STEP 11  Confirmation page with QR
  STEP 12  Confirmation email dispatched

TEAM MANAGEMENT (team events)
  Leader can:
    • Add member
    • Remove member (non-leader only)
    • Edit member
    • View member verification status
  Leader CANNOT:
    • Duplicate team member
    • Add same participant to multiple teams for same event
    • Exceed max team size
    • Bypass duplicate university email / student ID checks

SERVER-SIDE RULES (enforced in DB + API)
  • Unique: universityEmail, studentId, registrationId
  • Unique: teamName where appropriate
  • One registration per participant per event
  • One team per participant per team event
  • CTF: hard cap 5 members
  • Team registration uses DB transactions (all-or-nothing)

                    ▲  PART 12 · SECURITY ARCHITECTURE  ▲
═══════════════════════════════════════════════════════════════════════════

This is a CYBERSECURITY event website. Security is a FIRST-CLASS 
REQUIREMENT — non-negotiable.

AUTHENTICATION
  • NextAuth.js or secure session auth
  • Password hashing: argon2id or bcrypt (cost ≥ 12)
  • httpOnly + secure + sameSite cookies
  • Email verification required
  • Password reset via signed time-limited token
  • Brute-force protection (per-IP + per-account)
  • Session rotation on privilege change
  • Optional 2FA for admins

AUTHORIZATION
  • RBAC enforced server-side on every route
  • Permission checks on every API call
  • Deny by default — explicit allow required
  • Admin route gating at middleware + layout

INPUT VALIDATION
  • Zod schemas shared between client and server
  • Server validates independently of client
  • Reject unexpected fields (strict schemas)
  • Trim + normalize all string inputs
  • Validate emails, phones, URLs with proper regex

FILE UPLOAD SECURITY
  • Whitelist MIME types AND extensions
  • Verify magic bytes (not just extension)
  • Max file size per category (admin-configurable)
  • Rename files with random hashes
  • Store outside web root (or in private bucket)
  • Serve via signed URLs with short TTL
  • Strip EXIF metadata from images
  • Re-encode images with Sharp
  • Reject executable / script types entirely
  • Never serve user uploads from same origin as app

STUDENT ID PROTECTION (CRITICAL)
  • Private storage ONLY
  • Signed access URLs with short TTL (≤ 5 min)
  • Admin-only access — participants cannot view other participants' 
    IDs
  • NEVER in public API responses
  • NEVER in public profile pages
  • NEVER in search engine indexes
  • NEVER in public gallery or participant lists
  • Access logged per view (who, when, IP)
  • Upload validated server-side: extension + MIME + magic bytes + size
  • File names sanitized and randomized

SECURITY HEADERS
  • Content-Security-Policy (strict, nonce-based for inline)
  • Strict-Transport-Security (HSTS, 1 year, preload)
  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy: camera=(self), microphone=()
  • Cross-Origin-Opener-Policy: same-origin

CORS
  • Explicit whitelist of allowed origins
  • Never use wildcard in production
  • Credentials allowed only for whitelisted origins
  • Preflight responses cached appropriately

RATE LIMITING
  • Global: 100 requests / 15 min / IP
  • Registration submit: 10 / hour / IP
  • Sponsor submit: 10 / hour / IP
  • Login attempts: 5 / 15 min / IP + exponential backoff
  • Password reset: 3 / hour / email
  • Verification upload: 20 / hour / user

CSRF
  • CSRF tokens for all state-changing requests
  • SameSite=Strict cookies where possible
  • Double-submit cookie pattern if needed

DATABASE SECURITY
  • Least-privilege DB user (no superuser)
  • Parameterized queries only (Prisma handles)
  • No SQL/NoSQL injection possible (schema-validated)
  • Encrypted at rest (Postgres/TDE or host-level)
  • Encrypted in transit (TLS)
  • Backups encrypted + tested restores
  • PII fields identifiable and access-controlled

    • Settings changes

SECRETS MANAGEMENT

  • Separate secrets per environment (dev / staging / prod)

ERROR HANDLING

DEPENDENCY SECURITY
